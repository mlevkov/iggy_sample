# TD-2026-09-03: The Codecov upload fails silently for want of a token

**Source:** Dependabot first-wave triage (2026-09-23), checking what PR #37's
`codecov/codecov-action` bump actually did in CI.
**Status:** open

## Problem

ci.yml's Code Coverage job uploads `lcov.info` with `codecov/codecov-action`
and passes `CODECOV_TOKEN: ${{ secrets.CODECOV_TOKEN }}`, but the repository
has no such secret; as of 2026-09-23 it has no Actions or Dependabot secrets
at all. Codecov rejects the tokenless upload (`Upload queued for processing
failed: {"message":"Token required - not valid tokenless upload"}`), and the
step passes anyway because it sets `fail_ci_if_error: false`, so the job
stays green. Every main push run whose log is still retained was rejected
this way: 15 runs from 2026-07-05 to 2026-09-23, on codecov-action `v4`,
v4.6.0 and v7.1.1. One of them, 35910387482, was cancelled by ci.yml's
concurrency group after its upload step had already run. Older logs have
expired.

The README's "Automated Checks" list said "**Coverage**: Uploaded to
Codecov" until the pull request that filed this record; it now says the
upload is not authenticated and points here.

## Mitigations in place

- Coverage is still measured: the Code Coverage job runs the suite under
  cargo-llvm-cov, and pr.yml's Coverage Diff job prints the total on every
  pull request and warns below 60%.
- Nothing reads the Codecov side, so no decision rests on the missing data.
- ci.yml's Codecov step names this record, so an edit to it meets the
  trigger in place.

## Options

1. **Make the upload real.** Add `CODECOV_TOKEN` as a repository secret, and
   as a Dependabot secret too if Dependabot PRs should upload (their runs get
   no Actions secrets). Then let a rejected upload fail the job wherever a
   token is present, e.g. `fail_ci_if_error: ${{ secrets.CODECOV_TOKEN != ''
   }}`, so this cannot recur silently.
2. **Drop the upload.** Remove the Codecov step and the README line, keeping
   the local coverage run.

Either way, update the README's coverage line to match.

## Binding trigger

Whichever comes first: the next edit to ci.yml's coverage job, the next
major bump of `codecov/codecov-action`, or the next release (CONTRIBUTING's
release steps include resolving records bound to it).
