# TD-2026-09-02: Validate dependabot.yml in CI, and put the Dockerfile on an updater

**Source:** RustSec 2026-09 remediation, review rounds 1 and 2 (silent-failure
lens LOW; cross-cutting and correctness lenses on the Docker image).
**Status:** resolved (2026-11-06, with the `rust-version` 1.95 change; see Resolution)

## Problem

`.github/dependabot.yml` failed schema validation from 2025-12-01 until the
RustSec 2026-09 remediation, and nothing noticed for nine months: no check
failed and no Dependabot run or PR appeared, which reads the same as "nothing
to update". GitHub documents no alert for an invalid file. The file's header
now says to validate edits against the published schema, but that is a
convention, not a gate.

The Dockerfile has the same blind spot one level down. Its `FROM` images
(`rust:…-slim-bookworm`, `debian:bookworm-slim`) are pinned tags that nothing
updates, since dependabot.yml covers only the `cargo` and `github-actions`
ecosystems, and no workflow builds the image. That is how it sat unbuildable
from 2026-07-04 until 0.4.1.

## Mitigations in place

- dependabot.yml validates with 0 errors against
  https://json.schemastore.org/dependabot-2.0.json as of the remediation, and
  its header tells editors to run that validation.
- Once Dependabot runs, its weekly PRs make its absence noticeable again.
- CI's Dependency Policy job fails if the Dockerfile's Rust image drops below
  `rust-version`, the specific failure that happened. It does not catch a
  stale base image, or any other reason the image fails to build.

## Proposed fix

- A pr.yml job that validates dependabot.yml on every pull request, e.g.
  `pipx run check-jsonschema==<pinned> --builtin-schema vendor.dependabot
  .github/dependabot.yml` (ubuntu runners ship pipx; check-jsonschema bundles
  that schema). Deferred because it adds a third-party tool to CI, which is
  the maintainer's call; pin its version per TD-2026-07-07's supply-chain
  posture.
- A `package-ecosystem: "docker"` entry in dependabot.yml, so base-image
  bumps arrive as PRs; optionally a job that builds the image. The entry is
  an edit to dependabot.yml, so it belongs in the same change as the
  validation job.

## Binding trigger

Whichever comes first: the next edit to `.github/dependabot.yml` after this
record lands on main (the edits in the PR that filed it were validated by
hand), or the next change to `rust-version`, which TD-2026-07-02's iggy 0.11
upgrade will make.

## Resolution (2026-11-06)

The trigger fired with the iggy 0.11 upgrade's `rust-version` change
(1.93.0 -> 1.95.0, ADR-0001). Both halves of the proposed fix landed together.

- **Validation:** PR Checks' new "Dependabot Config" job runs
  `pipx run check-jsonschema==0.38.2 --builtin-schema vendor.dependabot
  .github/dependabot.yml` on every pull request.
  - 0.38.2 (2026-09-23) was the newest release more than two weeks old when it
    was pinned. 0.39.0 was 11 days old.
  - Verified both ways with that exact version. It accepts the current file.
    It rejects the 2025-12 file that silenced Dependabot, reporting both of its
    errors: the removed `reviewers` key and the
    `version-update:semver-prerelease` ignore type.
  - The job is not a required check. Adding it to the `main` ruleset is an
    admin action, left to the maintainer.
- **Updater:** dependabot.yml gains a `docker` ecosystem entry, grouped and on
  the same weekly schedule, so the Dockerfile's `FROM` images arrive as PRs.
  CI's existing check still fails a Rust image below `rust-version`.
  - `docker-compose.yaml` is deliberately not covered: its `apache/iggy` tag
    must move in lockstep with the Rust SDK, so a lone image bump would be a
    broken PR.
- **Not done:** the optional job that builds the image.
