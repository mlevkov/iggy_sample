# TD-2026-09-02: Validate dependabot.yml in CI

**Source:** RustSec 2026-09 remediation, review round 1 (silent-failure lens,
LOW).
**Status:** open

## Problem

`.github/dependabot.yml` failed schema validation from 2025-12-01 until the
RustSec 2026-09 remediation, and nothing noticed for nine months. GitHub
reports an invalid Dependabot config only on the repository's Dependabot
page: no check fails, and no Dependabot run or PR appears, which reads the
same as "nothing to update". The file's header now says to validate edits
against the published schema, but that is a convention, not a gate.

## Mitigations in place

- The file validates with 0 errors against
  https://json.schemastore.org/dependabot-2.0.json as of the remediation.
- Its header comment tells editors to run that validation, and why.
- Once Dependabot runs, its weekly PRs make its absence noticeable again.

## Proposed fix

A pr.yml job that validates the file on every pull request, for example
`pipx run check-jsonschema==<pinned> --builtin-schema vendor.dependabot
.github/dependabot.yml` (ubuntu runners ship pipx; check-jsonschema bundles
that schema). Deferred because it adds a third-party tool to CI, which is the
maintainer's call; pin its version per TD-2026-07-07's supply-chain posture.

## Binding trigger

The next edit to `.github/dependabot.yml`.
